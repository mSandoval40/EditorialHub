# Criterio Anti-Gigantismo UI

Este criterio aplica a todas las vistas de EditorialHub, para todos los usuarios y roles, con prioridad especial en las vistas operativas de `ADMIN` y `SOCIO`.

## Regla general

La plataforma debe evitar el gigantismo visual. Las pantallas deben sentirse contenidas, operativas y prudentes, no infladas.

## Principios

1. Una sola columna principal
- La estructura principal de cada pagina debe desarrollarse hacia abajo.
- No se deben partir las vistas en dos mitades grandes a lo ancho de la pantalla.
- Solo se permiten micro-columnas internas cuando realmente ayuden a ordenar informacion puntual.

2. Ancho contenido
- Cada pagina debe usar un ancho maximo razonable y centrado.
- La pantalla no debe sentirse de ancho infinito.
- La sensacion general debe ser de control, no de expansion.

3. Densidad util
- Debe verse mas informacion util por pantalla sin depender de scroll excesivo.
- Reducir aire muerto, alturas innecesarias y bloques demasiado altos.

4. Tarjetas y secciones compactas
- Padding moderado.
- Titulos moderados, no hero.
- Metadatos pequenos pero legibles.
- Botones y pills sobrios.

5. Formularios contenidos
- Inputs y acciones con tamanos razonables.
- Formularios cortos no deben ocupar todo el ancho disponible.
- Los formularios deben sentirse como modulos operativos, no como sabanas.

6. Assets subordinados
- Portadas, contraportadas, previews y manuscritos deben apoyar la operacion, no dominar la pantalla.
- En paneles operativos, la imagen nunca debe imponerse sobre la informacion.

7. Consistencia transversal
- El criterio aplica a:
  - Admin
  - Mi panel
  - Biblioteca
  - Publicar
  - vistas relacionadas
  - futuras secciones del sistema

## Preguntas de revision por seccion

Antes de dar por buena una pantalla, revisar:

- ¿La estructura principal baja en una sola columna?
- ¿El ancho general se siente contenido?
- ¿Hay bloques que ocupan mas altura de la necesaria?
- ¿Hay aire muerto?
- ¿Las imagenes o previews se ven demasiado protagonistas?
- ¿Se siente como panel operativo o como maqueta inflada?

## Regla de aplicacion

Cada nueva construccion y cada ajuste futuro debe respetar este criterio sin necesidad de que el usuario vuelva a repetirlo.
